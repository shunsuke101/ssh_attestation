# /digest — 月次ダイジェスト

対象月: **$ARGUMENTS**（空なら `Get-Date -Format yyyy-MM` で当月）

`inbox/` の生ログを、後から読み返す価値のある形に畳む。**Web 検索はしない**（収集は `/collect` の仕事）。手元にあるものだけで書く。

## 手順

1. 対象月 `YM` を確定する。日付は `Get-Date` で取り、推測しない。
2. `inbox/<YM>-*.md` を全て読む。1 件も無ければ「その月の収集記録なし」と報告して終了する。
3. `notes/**/*.md` のうち frontmatter の `added` が `<YM>` で始まるものを読む（`_` 始まりのテンプレートは除外）。
4. `docs/scope.md` の「中心的な問い」を読む。示唆の節はここに紐づける。
5. 既存の `digests/<YM>.md` があれば読み、**上書きではなく更新**する（人間の加筆を消さない）。
6. `digests/<YM>.md` を書く。

## 出力形式

```markdown
# <YM> ダイジェスト

収集回数: N 回 / 新着 M 件（high H / medium K / low L）/ 新規ノート J 件

## 今月の重要トピック

### 1. <トピック名>
（日本語 3–5 行。複数の新着を横断してまとめる。単なる列挙にしない）
関連: [<ノートのタイトル>](../notes/papers/....md), <URL>

### 2. ...
### 3. ...

## カテゴリ別の動き

### papers
（動きがあれば 2–4 行。なければ「目立った動きなし」）

### specs
### impl
### industry

## 自研究への示唆

`docs/scope.md` の「中心的な問い」に紐づけて書く。

- **問い 1（Evidence をどのレイヤで運ぶか）**: <今月の収集から言えること。無ければ「今月は材料なし」>
- **問い 2（後方互換性）**: ...
- **問い 3（Verifier の配置）**: ...
- **問い 4（Freshness）**: ...
- **問い 5（コストと運用）**: ...

## 次に追うべき論点

- <未読のまま残っている medium で、追う価値があるもの>
- <`/survey` の起点にすべきテーマ>
- <巡回先に足すべきソース>
```

**重要トピックは 3 点まで。** 全部を重要と書くと読み返さなくなる。該当が少ない月は 1〜2 点で構わない。

## 併せて提案すること（ファイルは書き換えない）

書き終えたら、以下をチャットで**提案だけ**する。実際の更新は人間の判断を待つ。

- `related-work/landscape.md` に足すべき項目・変えるべき分類
- `docs/sources.md` に足すべき巡回先（今月ヒットが多かった／少なすぎた源）
- `docs/scope.md` の除外条件に足すべきパターン（ノイズが多かった場合）

## やってはいけないこと

- Web を見に行く（`/collect` の役割）
- `inbox/` の内容を単に箇条書きで転記する（それは畳んだことにならない）
- 既存の `digests/<YM>.md` にある人間の加筆を消す
- `state/seen.jsonl` を触る
