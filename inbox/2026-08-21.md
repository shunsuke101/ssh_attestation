## specs

- **[high]** "Secure Evidence and Attestation Transport (SEAT)" — IETF Working Group（Active） — https://datatracker.ietf.org/group/seat/about/
  - **本研究とほぼ同じ問題を (D)TLS 向けに解く IETF WG が現に稼働している。** 憲章は「peer or mutual attestation for (D)TLS connections」の Standards Track 化。SSH は対象外。→ `notes/specs/seat-wg-charter.md`
- **[high]** "Remote Attestation with Exported Authenticators" — draft-fossati-seat-expat-03, Sardar et al., 2026-07-04 — https://datatracker.ietf.org/doc/draft-fossati-seat-expat/
  - SEAT WG の具体プロトコル案。`cmw_attestation` 拡張で post-handshake authentication の Certificate メッセージに attestation credential を載せ、passport / background-check 両モデルに対応。→ `notes/specs/draft-fossati-seat-expat.md`
- **[high]** "Remote ATtestation procedureS (RATS) Architecture" — RFC 9334, Birkholz et al., Informational, 2023-01 — https://www.rfc-editor.org/info/rfc9334
  - 土台文献。Attester / Verifier / Relying Party の役割分担と background-check / passport の 2 モデル。→ `notes/specs/rfc9334-rats-architecture.md`
- **[medium]** "Using Attestation in Transport Layer Security (TLS) and Datagram Transport Layer Security (DTLS)" — draft-fossati-tls-attestation-10, Tschofenig et al., 2026-07-23 — https://datatracker.ietf.org/doc/draft-fossati-tls-attestation/
  - TLS 1.3 ハンドシェイクで認証鍵を attestation セッションに束縛する案。**本文中で "This draft has been withdrawn" と明記**（datatracker 上は Active 表示なので注意）。設計の分岐点として読む価値あり
- **[medium]** "Remote Integrity Verification of Network Devices Containing Trusted Platform Modules" — RFC 9683, Informational, 2024-12 — https://www.rfc-editor.org/info/rfc9683
  - ネットワーク機器の TPM ベース完全性検証。運用面の先行例
- **[medium]** "A YANG Data Model for Challenge-Response-Based Remote Attestation (CHARRA) Procedures Using Trusted Platform Modules (TPMs)" — RFC 9684, Proposed Standard, 2024-12 — https://www.rfc-editor.org/info/rfc9684
  - challenge-response 型 RA の標準化例。freshness の扱い（中心的な問い 4）の参考
- **[medium]** "The Entity Attestation Token (EAT)" — RFC 9711, Proposed Standard, 2025-04 — https://www.rfc-editor.org/info/rfc9711
  - Evidence のトークン形式。SSH に載せる際のペイロード候補
- **[medium]** "Remote ATtestation procedureS (RATS) Conceptual Message Wrapper (CMW)" — RFC 9999, Proposed Standard, 2026-07 — https://www.rfc-editor.org/info/rfc9999
  - expat draft の `cmw_attestation` が依拠する形式。SEAT を読むなら必須
- **[medium]** "Epoch Markers" — draft-ietf-rats-epoch-markers-05, WG Document — https://datatracker.ietf.org/doc/draft-ietf-rats-epoch-markers/
  - nonce 以外の freshness 担保手段。中心的な問い 4 に直結
- **[medium]** "Direct Anonymous Attestation for the Remote Attestation Procedures Architecture" — draft-ietf-rats-daa-09, In WG Last Call — https://datatracker.ietf.org/doc/draft-ietf-rats-daa/
  - プライバシー保護。ホストの個体識別を避けたい場合
- **[medium]** "Reference Interaction Models for Remote Attestation Procedures" — draft-ietf-rats-reference-interaction-models-17, In WG Last Call — https://datatracker.ietf.org/doc/draft-ietf-rats-reference-interaction-models/
  - 相互作用パターンの整理。プロトコル設計の型として使える
- **[medium]** "Concise Reference Integrity Manifest" — draft-ietf-rats-corim-11, In WG Last Call — https://datatracker.ietf.org/doc/draft-ietf-rats-corim/
  - Reference Value の配布形式。中心的な問い 5（大規模運用）に直結
- **[medium]** "Attestation Results for Secure Interactions" — draft-ietf-rats-ar4si-10, WG Document — https://datatracker.ietf.org/doc/draft-ietf-rats-ar4si/
  - Attestation Result を「安全な相互作用」に使う形式。Relying Party 側の判断材料
- **[medium]** "Remote Attestation with Multiple Verifiers" — draft-ietf-rats-multi-verifier-00, WG Document — https://datatracker.ietf.org/doc/draft-ietf-rats-multi-verifier/
  - Verifier をどこに置くか（中心的な問い 3）の直接の議論
- **[medium]** "Use of Remote Attestation with Certification Signing Requests" — draft-ietf-lamps-csr-attestation — https://datatracker.ietf.org/doc/draft-ietf-lamps-csr-attestation/
  - CSR に attestation を添える。SSH 証明書発行に attestation を絡める設計（問い 3 の「CA 兼務」案）の類例
- **[low]** "Hardware-Rooted Attestation for Precision Time Protocol" — draft-ramki-ptp-hardware-rooted-attestation — https://datatracker.ietf.org/doc/draft-ramki-ptp-hardware-rooted-attestation/

## impl

- **[high]** "ssh-tpm-ca-authority — SSH Certificate Authority with device attestation" — Foxboron, Go, MIT — https://github.com/Foxboron/ssh-tpm-ca-authority
  - TPM の EK を照合して短命（5 分）SSH 証明書を発行する CA。**SSH 証明書に device attestation を絡める設計の実物。** POC 品質。→ `notes/impl/ssh-tpm-ca-authority-device-attested-certs.md`
- **[high]** "HardwareProtectedSsh — Enforce TPM remote platform attestation for Linux authentication" — hdracer, C++, GPL-3.0 — https://github.com/hdracer/HardwareProtectedSsh
  - **双方向**の TPM platform attestation を SSH 認証に強制する PAM モジュール。attestation ライブラリ + PAM + TSS 連携。研究デモ規模（約 63 commits, 7 stars）。→ `notes/impl/hardwareprotectedssh-bidirectional-tpm-attestation.md`
- **[medium]** "OpenSSH 10.5" — 2026-08-11 — https://www.openssh.org/releasenotes.html
  - 10.5 自体に attestation の新規要素は無いが、**10.0 のノートに "support FIDO tokens that return no attestation data" と "a work-in-progress tool to verify FIDO attestation blobs" の記述**あり。OpenSSH 本体が attestation blob 検証に着手している前例として重要
- **[medium]** "ssh-tpm-agent v0.9.0" — Foxboron, 2026-05-04 — https://github.com/Foxboron/ssh-tpm-agent
  - key confirm dialog と process chain 表示を追加。v0.8.0 で SSH certificate signing 対応。リリースノート上は attestation / EK / AK への直接の言及なし

## papers

- **[medium]** "SSH-Passkeys: Leveraging Web Authentication for Passwordless SSH" — Kayali, Schmitt, Roesner — arXiv:2507.09022, 2025-07-11 — https://arxiv.org/abs/2507.09022
  - WebAuthn を PAM 経由で SSH に統合。40 名のユーザ実験で critical security error が 90% 減。**arXiv 上で "SSH attestation" に引っかかる実質唯一の SSH 統合論文**だが、主眼は passwordless の UX で attestation そのものではないため medium 止まり。→ `/survey` の第一候補
- **[medium]** "Remote attestation of SEV-SNP confidential VMs using e-vTPMs" — Narayanan et al. — arXiv:2303.16463, 2023-03-29 — https://arxiv.org/abs/2303.16463
  - 永続状態を持たない ephemeral vTPM で RA を成立させる。SSH とは無関係だが、Attester 側の実装部品として使える
- **[medium]** "Vordr: Verifiable, Scalable and Anonymous Remote Attestation for Confidential Virtual Machines" — Koirala et al. — IACR ePrint 2026/1472, 2026 — https://eprint.iacr.org/2026/1472
  - 匿名 RA。プライバシー（DAA 系）の最新動向
- **[medium]** "SEDAT: Security Enhanced Device Attestation with TPM2.0" — arXiv:2101.06362, 2021 — https://arxiv.org/abs/2101.06362
  - TPM 2.0 ベースの device attestation。著者名未確認（要一次情報）
- **[low]** "Claimed or Attested? A Commit-Signature Dataset and Identity Trust Tiers across the World of Code" — Mockus — arXiv:2607.06194, 2026-07-07 — https://arxiv.org/abs/2607.06194
  - git commit 署名の実態調査。SSH 署名の普及率データとしては使えるが、ホスト attestation とは別問題
