## papers

- **[high]** "Attestation-based scheme for validating peering setups for critical infrastructure protocols" — Sheth, Bhandari, Voit, Sulzen, Brockners (Cisco Technology Inc.), US 11165861 B2, 出願 2020-02-06 / 登録 2021-11-02 / 優先日 2019-04-05 — <https://patents.google.com/patent/US11165861B2/en>
  - **SSH に attestation を組み込む granted patent。本研究の先行技術として決定的。** ただし明細書の SSH 実施例は **SSH サーバー → クライアント**方向（サーバーが自分の完全性情報をクライアントに送る）で、本研究が採るクライアント → サーバー方向は記述されていない。nonce ベースの challenge-response と TPM 署名、セッション中の継続的な再提示まで書かれている。**`sources.md` で 2 回連続失敗していた一次確認が今回成功した。**
- **[high]** "PRA-TLS: Attestation of a Client Application for TEE" — Sasaki, Ishikawa, Takefusa, Oguchi (お茶の水女子大 / ROIS / 大妻女子大 / NII), arXiv:2610.06061, 2026-10-05 — <https://arxiv.org/abs/2610.06061>
  - **クライアント側アプリケーションの attestation を TLS ハンドシェイクに統合する提案。** Verifier（サーバー）が ServerHello の nonce を challenge として出し、クライアントが `hash(コードハッシュ ‖ nonce)` を Evidence として返す。**本研究の server challenge / client response と構造が一致する唯一の最新研究。** Tamarin Prover で形式検証。Intel SGX で実装。ハンドシェイク遅延は中央値 1301 ms（素の TLS は 2.758 ms）。SSH への言及はなし。
- **[medium]** "LURK-T: Limited Use of Remote Keys With Added Trust in TLS 1.3" — Shobiri et al., arXiv:2506.12026, 2025-05-21 — <https://arxiv.org/abs/2506.12026>
  - TLS 1.3 で秘密鍵の使用を TEE に閉じ込め信頼を加える方式。鍵の保護と attestation の組み合わせという点で問い 3 / 問い 4 の部品になりうる。
- **[medium]** "To attest or not to attest, this is the question – Provable attestation in FIDO2" — Bindel, Gama, Guasch, Ronen, IACR ePrint 2023/1398, 2023-09-18 — <https://eprint.iacr.org/2023/1398>
  - FIDO2 の attestation を形式的に扱った仕事。OpenSSH の `-sk` 鍵 attestation（→ `notes/impl/openssh-protocol-extensions.md`）の理論的裏付けとして引ける。
- **[medium]** "Attestation Proof of Association – provability that attestation keys are bound to the same hardware and person" — Verheul, IACR ePrint 2024/1444, 2025-01-19 — <https://eprint.iacr.org/2024/1444>
  - 複数の attestation 鍵が同一ハードウェアに属することの証明可能性。クライアントの SSH 鍵と AK の束縛（問い 4）に効く可能性。
- **[low]** "Kettle: Attested builds for verifiable software provenance" — Asad, Arko, arXiv:2605.08363, 2026-05-08 — <https://arxiv.org/abs/2605.08363>
  - ビルドの attestation。Reference Value の出所という観点（問い 5）での背景。
- **[low]** "DID Link: Authentication in TLS with Decentralized Identifiers and Verifiable Credentials" — Rodriguez Garzon et al., arXiv:2405.07533, 2025-01-13 — <https://arxiv.org/abs/2405.07533>
  - TLS の認証を DID で置き換える系統。attestation ではないが「チャネル認証の代替モデル」として背景。
- **[low]** "PIRANHAS: PrIvacy-Preserving Remote Attestation in Non-Hierarchical Asynchronous Swarms" — Hofmann et al., IACR ePrint 2025/2228, 2026-04-02 — <https://eprint.iacr.org/2025/2228>
  - プライバシー保護 attestation。クライアント端末を Attester にするときのプライバシー問題（問い 3 の周辺）の背景。
