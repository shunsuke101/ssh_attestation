## papers

- **[high]** "Network security by integrating mutual attestation" — Cisco Technology Inc.、発明者 Sheth, Bhandari, Voit, Sulzen, Brockners（検索スニペットによる）、US 11321465 B2 — <https://patents.google.com/patent/US11321465B2/en>（USPTO PDF: <https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/11321465>）
  - **本研究にとって最大級の先行技術リスク。** 既読の US 11165861（同じ発明者陣、サーバー → クライアント方向）とは別ファミリーで、検索スニペットによれば **「サーバーが暗号セッション開始のメッセージを送り、クライアントの応答を受け、その応答（TPM による完全性証明のメタデータを含みうる）からクライアントの trust level を判定し、ハンドシェイクを続けるか決める」**という**クライアント → サーバー方向**の方法を主張している。対象プロトコルは SSH / TLS / SSL / IPsec。優先権の基礎となる 2019-04 の仮出願の 1 つが "Ensuring trusted client-server relationships for Secure Shell" という題。
  - **一次情報未読**（Google Patents・Justia とも WebFetch 権限拒否）。クレーム本文・出願日・登録日・SSH 実施例の詳細は未確認。**次回最優先で一次確認してノート化すること。**
- **[high]** "Network security by integrating mutual attestation" — Cisco Technology Inc.、US 11934525 B2（US 11321465 の継続、出願番号 17/712,499 と検索スニペットにある） — <https://patents.google.com/patent/US11934525B2/en>（USPTO PDF: <https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/11934525>）
  - 上記の継続出願。スニペットによれば背景で SSH / TLS セッションの両端が侵害されうることを述べ、**SSH の相互認証を attestation で拡張する**と書いている。一次情報未読。
- **[medium]** "Establishing Secure Communication Channels Using Remote Attestation with TPM 2.0" — Wagner, Birnstill, Beyerer, STM 2020 (LNCS, pp. 73–89) — <https://doi.org/10.1007/978-3-030-59817-4_5>
  - 既存の TPM attestation プロトコルに relay attack の変種が成立することを示し、TPM だけで共有鍵を確立する軽量な TPM 2.0 attestation プロトコルを提案（相互 attestation、PFS、Tamarin で解析）。**Evidence を通信路に束縛する問題（問い 4）**の先行研究。SSH 固有ではない。
- **[low]** "Protecting SSH authentication with TPM 2.0" — Iooss, SSTIC 2021 — <https://www.sstic.org/2021/presentation/protecting_ssh_authentication_with_tpm_20/>
  - tpm2-pkcs11 で SSH 鍵を TPM に入れたときの安全性の検討。鍵保護だけで attestation は扱わない。背景。

### メーリングリストの観察

- **`ssh@ietf.org`**: **"zero trust discussion (was: some other unrelated subject)"**（Stephen Farrell〔chair〕, 2026-10-16）— <https://mailarchive.ietf.org/arch/msg/ssh/rMzJDfh6hiMdyWxnpQ-uQsyaV04/>
  - Dick Brooks が "Deprecation of Compression - Scope" スレッド等で zero trust の話題を繰り返し持ち込んだことへの chair の返信。要旨: **WG で扱うには draft を書いて採択を求める必要があり、SSH 実装者の支持がなければ採択は見込みにくい**。本文に attestation / TPM / device posture の語は無い。
  - （解釈）**SSH に device trust 系の機能を入れる提案は、現状 WG では「実装者の支持がない話題」と見られている**ことの一次的な証拠。標準化を狙うなら OpenSSH 側（Damien Miller ら）の関心を先に得る必要がある、という戦略上の示唆になる。
  - 他は "Deprecation of Compression - Scope"（10-12〜16、長スレッド）、`draft-kario-gss-keyex-pqc-00` の採択コール（〜10-22）、SSHM 中間会議（10-07）の議事メモ、IETF 127 セッション申請。attestation 関連は無し。
- **`seat@ietf.org`**: "Proposed attack vector for seat-use-cases - Encrypted Evidence and Blind Envelope Substitution"（Nathanael Ritz, 10-13）、"Feedback on draft-ounsworth-rats-privacy-framework"（10-13〜16）。Evidence のすり替え攻撃は**問い 4（束縛）**に、プライバシー枠組みへのフィードバックは**クライアントを Attester にするときの障壁**に関わる。SSH の言及は依然なし。
- **`rats@ietf.org`**（**初巡回**）: endorsements の IESG ballot、network-device-subscription への DISCUSS、RFC 9711 (EAT) の technical errata 報告が 5 件（10-01〜02）、Multi-Verifier draft のレビュー。SSH・key binding・`draft-reddy-rats-key-binding` の言及はなし。

## impl

- **[medium]** "Integrating Intel TDX remote attestation into SSH" — Fabian Wesemann（Flensburg University of Applied Sciences）、FOSDEM 2025 Attestation devroom、2025-02-02 — <https://fosdem.org/2025/schedule/event/fosdem-2025-4901-integrating-intel-tdx-remote-attestation-into-ssh/>（スライド: <https://fosdem.org/2025/events/attachments/fosdem-2025-4901-integrating-intel-tdx-remote-attestation-into-ssh/slides/237278/Integrati_BydUSZ6.pdf>）
  - **OpenSSH を改変した challenge-response 型の attestation プロトタイプ。** クライアントが challenger / Relying Party となり、サーバーが TDX 内で動いていることを証明できる場合だけ接続する。Verifier に Microsoft Azure Attestation を使う。**通常の SSH 認証・暗号化が済んだ後に実行**し、sshd とセッション間のメッセージを監視する特権プロセスを要する（検索スニペットによる）。
  - 方向はサーバー → クライアントなので `docs/scope.md` に従い `medium`。ただし **OpenSSH に challenge-response を組み込んだ実装例**として、問い 1（認証後に運ぶ案）の比較対象になる。スライドは WebFetch 権限拒否で未読。
- **[low]** "SSH authentication using user and machine identities" — Morten Linderud, All Systems Go 2024 — <https://cfp.all-systems-go.io/all-systems-go-2024/talk/JCJ9YT/>
  - 既読 `ssh-tpm-ca-authority` の設計を説明した講演（SSO の ID と TPM の device attestation を組み合わせて短命 SSH 証明書を発行）。既存ノートの補足資料。
- GitHub 横断検索（`ssh attestation in:name,description`, sort=stars）— 13 件。新規 2 件はいずれも除外: `M1lo25/CS50FinalProject`（XZ バックドアの学習課題、attestation の技術的中身なし）、`shunsuke101/ssh_attestation`（このリポジトリ自身）。既登録の `aliyun/credagent` は description が「attestation を通った process にだけ平文資格情報を渡す」と読めたが SSH との関係はなく、`low` のまま。
- OpenSSH — 最新は依然 10.6 / 10.6p1（2026-10-06）。新着なし。
