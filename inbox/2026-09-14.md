# 2026-09-14 の収集

対象カテゴリ: papers, specs, impl, industry

## papers

- **[high]** Identity Crisis in Confidential Computing: Formal Analysis of Attested TLS — Sardar, Moustafa, Aura, AsiaCCS 2026 — https://doi.org/10.1145/3779208.3785387
  - ProVerif で attested TLS 2 方式（Interoperable RA-TLS / draft-fossati-tls-attestation）を形式検証し、両方が server identity・server authentication・compound authentication を満たさず diversion attack を受けることを示した。
- **[high]** Session Attestation for Unmodified TLS Services in Confidential Virtual Machines — Gu and Ma, arXiv 2026-09-08 — https://arxiv.org/abs/2609.09668
  - TLS ライブラリもアプリもを一切改変せず、OS 層の observer が ServerHello の ephemeral 公開鍵を観測して Evidence に束縛する SessionLatch を提案。後方互換の取り方の実例。
- **[high]** Integrating Remote Attestation with Transport Layer Security — Knauth et al., arXiv 2018 (v2 2019) — https://arxiv.org/abs/1801.05863
  - SGX の remote attestation を X.509 証明書に埋め込んで TLS 確立に統合する原典。secure channel への attestation 統合という問題設定そのものの出発点。
- **[medium]** Grimlock: Guarding High-Agency Systems with eBPF and Attested Channels — Wu et al., arXiv 2026-05 — https://arxiv.org/abs/2605.27488
  - eBPF によるトラフィック傍受と、標準 TLS 1.3 に束縛した post-handshake attestation を組み合わせる。post-handshake 側の実例。
- **[medium]** ACTS: Attestations of Contents in TLS Sessions — Della Monica et al., IACR ePrint 2026/755 — https://eprint.iacr.org/2026/755
  - TLS セッションの内容そのものに対する attestation。RATS 系の platform attestation とは別軸だが「何を証明対象にするか」の整理に使える。
- **[medium]** Transparent Attested DNS for Confidential Computing Services — arXiv 2025-03 — https://arxiv.org/abs/2503.14611
  - attestation の検証結果を DNS 層で透過的に配る方式。Verifier の置き場所（問い 3）の一案。
- **[medium]** "They don't care about this": A Systematic Study of TEE Build Reproducibility in the Wild — arXiv 2026-09 — https://arxiv.org/abs/2609.11411
  - TEE 向けビルドの再現性の実態調査。Reference Value をどう作るか（問い 5）の前提に効く。
- **[low]** Attesting Outputs and Delegation Ancestry in Multi-Agent AI Systems — Liu and Yu, arXiv 2026-08-31 — https://arxiv.org/abs/2608.30387
  - マルチエージェント AI の出力に対する二層 attestation。語が同じだけで対象が違う。
- **[low]** TEE-Assisted Authenticated MPC for Resource Constrained Edge Intelligence — IACR ePrint 2026/1733 — https://eprint.iacr.org/2026/1733
  - TEE を使った MPC。attestation は前提として使うのみ。

## specs

IETF SSHM WG の **Related Internet-Drafts**（WG 文書ではない個人 I-D）を今回初めて列挙した。前回まで WG 文書欄しか見ておらず取りこぼしていた枠。

- **[high]** A Pre-Authentication Mechanism for SSH — draft-gutmann-ssh-preauth-06, 2026-08-03 — https://datatracker.ietf.org/doc/draft-gutmann-ssh-preauth/
  - SSH の ID string の Comment 欄に `C=<challenge>` / `R=<response>` を載せる。**プロトコル自体を一切変更せず**、ID string 交換という最初期の段階に追加データを流す先例。attestation には言及していないが、問い 1・2 に直結する。
- **[medium]** Lightweight Secure Shell (SSH) Signature Format — draft-josefsson-sshsig-format-04, 2026-07-22 — https://datatracker.ietf.org/doc/draft-josefsson-sshsig-format/
  - sshsig のスタンドアロン署名形式の仕様化。Evidence を SSH の外で署名オブジェクトとして運ぶ場合の器の候補。
- **[medium]** X.509v3 ML-DSA Certificates for the Secure Shell (SSH) Protocol — draft-rpe-ssh-x509-mldsa-01, 2026-07-01 — https://datatracker.ietf.org/doc/draft-rpe-ssh-x509-mldsa/
  - SSH で X.509 証明書を使う系統。attestation を証明書拡張で運ぶ設計（問い 1）を採るなら、OpenSSH 証明書ではなくこちらに乗る選択肢がある。
- **[medium]** Channel Binding Identifiers for Secure Shell Channel — draft-williams-sshv2-channel-bindings-00 — https://datatracker.ietf.org/doc/draft-williams-sshv2-channel-bindings/
  - 失効済みの古い個人 I-D だが、SSH に channel binding 識別子を定義しようとした唯一の文書。問い 4（セッション束縛）の先行事例として押さえる。
- **[low]** Commercial National Security Algorithm (CNSA) Suite 2.0 Profile for SSH — draft-becker-cnsa2-ssh-profile-05, 2026-07-21 — https://datatracker.ietf.org/doc/draft-becker-cnsa2-ssh-profile/
- **[low]** Module-Lattice Key Exchange in SSH — draft-harrison-sshm-mlkem-02, 2026-05-27 — https://datatracker.ietf.org/doc/draft-harrison-sshm-mlkem/
- **[low]** Stateless Hash-Based Signatures for Secure Shell (SSH) — draft-josefsson-ssh-sphincs-02, 2026-05-06 — https://datatracker.ietf.org/doc/draft-josefsson-ssh-sphincs/
- **[low]** ML-DSA Public Key Algorithms for the Secure Shell (SSH) Protocol — draft-rpe-ssh-mldsa-03, 2026-04-16 — https://datatracker.ietf.org/doc/draft-rpe-ssh-mldsa/
- **[low]** SSH Support of ML-DSA — draft-sfluhrer-ssh-mldsa-08, 2026-08-28 — https://datatracker.ietf.org/doc/draft-sfluhrer-ssh-mldsa/
- **[low]** Composite ML-DSA Signatures for SSH — draft-sun-ssh-composite-sigs-03, 2026-07-06 — https://datatracker.ietf.org/doc/draft-sun-ssh-composite-sigs/

- sshm@ietf.org ML — `https://mailarchive.ietf.org/arch/browse/sshm/` は **404**、`https://mailarchive.ietf.org/arch/search/?email_list=sshm&q=attestation` は **403**。**3 回連続で失敗、依然未巡回。** seat の方は同じ `/arch/browse/seat/` 形式で取れているので、リスト名が `sshm` でない可能性がある。次回は datatracker の SSHM WG ページ内の「Mailing list archive」リンクを実際に辿って正しい URL を確認すること。
- IETF datatracker 検索 API（ssh）— `&order_by=-time` を付けると **HTTP 400**。パラメータ無しなら取得できるが、返る順序が登録順で古い文書が並ぶため新着検出には向かない。SSHM WG の文書一覧ページを見る方が確実。
- ACM DL（`https://dl.acm.org/doi/10.1145/3779208.3785387`）— **403**。Identity Crisis の書誌は著者の公開リポジトリ（CCC-Attestation/formal-spec-id-crisis）の BibTeX で確認した。
- arXiv PDF 直取り（`arxiv.org/pdf/...`）— PDF のバイナリが読めず内容抽出に失敗。**`https://arxiv.org/html/<ID>v1` を使えば読める**（2609.09668 で確認）。次回以降はこちらを使うこと。
