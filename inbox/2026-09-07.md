## specs

SEAT WG がこの 1 ヶ月半で大きく動いており、今回の収穫の大半がここ。

- **[high]** Security Goals and Use Cases for Integrating Remote Attestation with Secure Channel Protocols — draft-ietf-seat-use-cases-00, 2026-07-20 — https://datatracker.ietf.org/doc/draft-ietf-seat-use-cases/
  - SEAT の**WG document**。security goals 10 件と use case 10 件を規定。**SSH への言及は本文に一切なく、スコープは TLS 1.3 / DTLS 1.3 に限定**されている。→ `notes/specs/draft-ietf-seat-use-cases.md`
- **[high]** Pre-, Intra- and Post-handshake Attestation — draft-usama-seat-intra-vs-post-04, 2026-07-06 — https://datatracker.ietf.org/doc/draft-usama-seat-intra-vs-post/
  - Evidence の署名時刻でattestation を 3 分類し trade-off を整理。intra-handshake は Evidence 生成だけで 140–1020 ms かかるという数字を挙げる。→ `notes/specs/draft-usama-seat-intra-vs-post.md`
- **[high]** Secure Evidence and Attestation Transport (SEAT) Architecture — draft-many-seat-architecture-00, 2026-07-04 — https://datatracker.ietf.org/doc/draft-many-seat-architecture/
  - RATS ロールをトランスポート端点に対応づけ、Evidence のセッション束縛を 3 条件（binding value → directional binder → Evidence への署名焼き込み）に分解。適用対象を "secure channel establishment protocols" 一般としている。→ `notes/specs/draft-many-seat-architecture.md`
- **[high]** Application-Layer Transport for Exported Authenticators and Attestation — draft-reddy-seat-expat-transport-02, 2026-08-25 — https://datatracker.ietf.org/doc/draft-reddy-seat-expat-transport/
  - **ALTEA**。RFC 9261 の Exported Authenticator を運ぶアプリ層トランスポートを新設。HTTP binding と shim mode の 2 つ。TLS 本体を変えない代償にアプリ層に土管を引いた形。→ `notes/specs/draft-reddy-seat-expat-transport.md`
- **[medium]** Using Attestation in Transport Layer Security (TLS) and Datagram Transport Layer Security (DTLS) — draft-fossati-seat-early-attestation-06, 2026-08-05 — https://datatracker.ietf.org/doc/draft-fossati-seat-early-attestation/
  - **既知文書の改名**。`draft-fossati-tls-attestation`（SEEN 済、`-10` で withdrawn）と同一タイトルで SEAT 系列に移った。`notes/specs/draft-fossati-seat-expat.md` の「系譜」表を次回更新すること。
- **[medium]** Evidence Encoding for Hardware Security Modules — draft-ietf-rats-pkix-key-attestation-07, 2026-07-05 — https://datatracker.ietf.org/doc/draft-ietf-rats-pkix-key-attestation/
  - HSM の鍵 attestation の Evidence 符号化。「鍵が本当にハードウェア内で生成され外に出ない」ことの証明形式で、SSH ホスト鍵の非可搬性を主張する部分の部品になりうる。
- **[medium]** Bridging Remote Attestation with Secure Channel Protocol Proxies — draft-ritz-seat-proxies-00, 2026-07-05 — https://datatracker.ietf.org/doc/draft-ritz-seat-proxies/
  - 中継・プロキシ越しの attestation。SSH の踏み台（ProxyJump）構成に対応する論点で、後で効く見込み。
- **[medium]** Balancing Security and Deployability in the Selection of Attested TLS Protocol — draft-zhang-seat-selection-01, 2026-07-06 — https://datatracker.ietf.org/doc/draft-zhang-seat-selection/
  - 方式選択の判断基準。中心的な問い 2（段階的導入）と近い。
- **[low]** Post-Quantum/Traditional Hybrid Key Exchange with the Module-Lattice-Based Key-Encapsulation Mechanism for Use in SSH — RFC 10042, 2026-08 — https://www.rfc-editor.org/info/rfc10042
  - SEEN 済 `draft-ietf-sshm-mlkem-hybrid-kex` の RFC 化。PQC であり attestation とは無関係だが、SSHM WG の版管理として記録。

## 今回の判定メモ

`high` は 5 件で上限ちょうど。うち 4 件が SEAT WG の文書で、いずれも「attestation を secure channel に統合する」という本研究と同じ問題を TLS の上で解いている。**SEAT が扱っている問題は本研究の問題そのものであり、違いは対象プロトコルだけ**という状況がはっきりしてきた。これは脅威でもあり追い風でもある。次の `/survey` は SEAT 系文書群を横断して「TLS 向けの設計判断のうち、SSH で変わるものはどれか」を洗い出すのが良いと思う。
